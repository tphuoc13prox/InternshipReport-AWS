# Summary Report: "Fireside Chat with Dr. Werner: Navigating the Future of Cloud & AI in Vietnam"

### Event Objectives

- Understand how large-scale technology systems are designed and operated for reliability.
- Learn practical principles of operational excellence from Amazon's engineering experience.
- Understand how AI is changing the role of software engineers.
- Explore the skills required for engineers to remain effective in an AI-driven technology environment.
- Gain insights into the importance of systems thinking, continuous learning, ownership, and communication.

### Speakers

- **Dr. Werner Vogels – Chief Technology Officer and Vice President, Amazon**

### Event Information

- **Event:** Fireside Chat with Dr. Werner: Navigating the Future of Cloud & AI in Vietnam
- **Date:** Friday, October 2, 2026

- **Organizers:** AWS First Cloud Journey × Amazon

### Key Highlights

#### Learning from Real Operational Failures

Amazon's experience with a major database outage demonstrated the importance of understanding actual system usage instead of blindly relying on existing technologies. By analyzing actual workloads, engineers found that 70% of database operations were simple key-value queries, while only 10% genuinely required relational database capabilities. This insight contributed to the development of Amazon's distributed key-value technology, which became the foundation for Dynamo and DynamoDB.

#### Operational Excellence

The discussion highlighted four important practices:

- Measuring system performance at the P99.9 percentile.
- Designing systems with the assumption that failures will happen.
- Using GameDays to deliberately test failure recovery.
- Using cloud's pay-as-you-go model to improve operational responsibility and service quality.

#### The Renaissance Developer

Dr. Vogels introduced the idea that modern developers need more than programming skills. Rather than being replaced by AI, a Renaissance Developer should have:

- Curiosity and continuous learning
- Systems thinking
- Ownership
- T-shaped expertise
- Strong communication skills

#### AI as a Catalyst, Not a Replacement for Engineers

AI can significantly accelerate prototyping and automate repetitive work, but its output still requires human evaluation for security, edge cases, and efficiency. Human judgment, creativity, empathy, and professional responsibility remain important.

### Key Takeaways

- Systems should be designed based on real usage and real problems, rather than simply adopting existing technologies because they are popular.
- Failure should be expected and planned for. Reliable systems require testing, monitoring, and automated recovery.
- AI changes the role of engineers rather than eliminating it. Engineers need to move beyond simply writing code and become responsible for the complete system.
- Continuous learning is essential because programming languages, frameworks, cloud technologies, and AI tools continuously evolve.
- Systems thinking is increasingly important, especially when working with distributed cloud systems.
- Human judgment and ownership remain critical. AI-generated code still needs to be evaluated for security, correctness, edge cases, and efficiency.

### Applying to Work

The lessons from the event can be applied directly to my FCAJ project and AWS learning activities:

- **Systems thinking:** Understand how different AWS services work together instead of learning each service independently. For example, a complete AWS application may involve data collection, storage, model training, inference, monitoring, and user interaction.
- **"Everything Fails All the Time":** Design applications with failure in mind. In my project, this can be applied through monitoring, error handling, service isolation, and proper cleanup of AWS resources.
- **Renaissance Developer:** Expand beyond AI/ML model development and understand cloud infrastructure, databases, security, system architecture, and communication.
- **Responsible use of AI:** AI tools can accelerate development, but I should still verify generated code, understand its behavior, and remain responsible for the final system rather than blindly relying on AI-generated solutions.

### Event Experience

The Fireside Chat provided a valuable perspective on how cloud and AI technologies are approached at a large technology organization. Instead of focusing only on specific tools or technologies, the discussion emphasized engineering principles, system reliability, continuous learning, and human responsibility.

The concept of the Renaissance Developer was particularly relevant to my development as an AI student because it showed that becoming a strong engineer requires both technical depth and broader understanding across different areas of technology.
